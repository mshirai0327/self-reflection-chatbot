# メモリ・会話コンテキスト改善計画

## 概要
現在のReflectaは、ユーザーとの「直近の会話のキャッチボール」が成立しにくい（短期記憶の欠如）という課題と、ChromaDBが挨拶などの「意味の薄い記憶」で埋め尽くされている（長期記憶の汚染）という2つの課題を抱えています。
これらを解決し、より自然で知的、かつ人間らしい記憶運用を実現するための改修計画です。

## 現状の課題
1.  **短期記憶（Context）の欠如**
    *   現在、LLMへの入力には「現在のステータス」と「ChromaDBから検索した断片的な記憶」しか渡されていません。
    *   **問題点**: 「直前の会話の流れ」がプロンプトに含まれていないため、「さっきの話」を参照できず、会話がぶつ切りになります。
2.  **長期記憶（ChromaDB）の品質低下**
    *   ユーザーの全ての発言を無条件でChromaDBにベクトル保存しています。
    *   **問題点**: 「こんばんは」「元気？」といった汎用的な挨拶が大量に蓄積され、類似検索をかけた際にこれらのノイズが上位にヒットしてしまい、本当に重要な「ユーザーの好み」や「過去の出来事」が呼び出せなくなっています。

---

## 改善フェーズ

### フェーズ1: 短期記憶（会話履歴）の注入 (即時対応)
直近の会話の流れをLLMに認識させ、スムーズな応答を実現します。

**実装内容:**
1.  **Chat API (`backend/src/app/api/chat/route.ts`) の改修**
    *   リクエスト時に、Prisma経由で `ChatLog` テーブルから対象チャットの「直近10件程度」の会話履歴を取得します。
    *   取得した履歴を `generateResponse` 関数に渡せるように引数を拡張します。
2.  **LLM Logic (`backend/src/lib/llm.ts`) の改修**
    *   `generateResponse` 内でメッセージを構築する際、System Instructionの直後に `History` ブロックを追加します。
    *   単純なテキスト結合、またはLangChainのMessageHistory形式でプロンプトに組み込みます。

**期待などの効果:**
*   「それはどういう意味？」といった指示語が通じるようになります。
*   会話のテンポが良くなり、AIが唐突な話題転換をしなくなります。

### フェーズ2: 長期記憶の選別と要約 (高品質化)
ChromaDBを「ゴミ箱」ではなく「重要なエピソード記憶」の保管庫にします。

**実装内容:**
1.  **全件保存の停止**
    *   `/api/chat` での応答直後に行っている `addMemory`（ChromaDBへの保存）を**廃止**、または条件付きに変更します。
2.  **記憶の要約・抽出プロセスの導入**
    *   以下のいずれかのタイミングで、「記憶の定着」処理を実行します。
        *   会話が一定数進んだとき（例: 5往復ごと）
        *   セッション終了時（または「内省」API呼び出し時）
    *   **処理フロー**:
        1.  直近の会話ログをLLMに渡し、「長期的に覚えておくべき重要な事実（ユーザーの趣味、新しい合意事項、ペルソナの感情変化など）」を抽出・要約させます。
        2.  要約された内容**のみ**を ChromaDB に保存します。
            *   *（例: "ユーザー: こんばんは" → 保存しない）*
            *   *（例: "ユーザー: 実は猫を飼い始めたんだ" → "ユーザーは猫を飼い始めた" として保存）*

**期待される効果:**
*   検索クエリに対して、意味のある記憶だけがヒットするようになります。
*   ベクトルDBの容量節約と検索精度の向上が見込めます。

---

## 実行プラン

まず **フェーズ1（短期記憶の注入）** を優先的に実装し、会話体験を改善します。
その後、フェーズ2（長期記憶の戦略変更）について、具体的なトリガー（いつ保存するか）を検討し実装します。
