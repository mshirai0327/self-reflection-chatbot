# Reflecta プロジェクト開発ガイドライン

このドキュメントは、Reflecta の開発における共通ルールと設計思想をまとめたものです。Antigravity は常にこのルールを遵守してください。

## 1. 基本方針
- **言語**: ユーザーへの応答、コードコメント、思考プロセス（Thinking）はすべて **日本語** で行います。
- **修正の透明性**: コードを修正・変更する場合は、必ず **その理由と意図** を添えて説明してください。
- **ドキュメント重視**: 関数や複雑なロジックには **JSDoc** を積極的に付与し、意図を明文化してください。
- 内省処理は特に重要です。ロジックには詳細なコメントを入れて、ロジックを`reflection-process.md`に記載してください

## 2. 用語の定義
- **ベクトルストア (Vector Store)**: ChromaDB を指します。「ベクトルデータベース」や「メモリDB」ではなく、この用語に統一してください。
- **内省 (Self-Reflection)**: AI が自らの行動を振り返り、ステータスや恒久記憶を更新する処理を指します。
- **ペルソナ (Persona)**: AI 人格そのものを指します。ユーザーとは独立したエンティティとして扱います。

## 3. モデルの役割分担
- **推論・内省用**: `gemini-*-pro`（例: `gemini-2.5-pro`）を使用します。複雑なロジックや JSON 生成が必要な場面で活用してください。
- **対話・応答用**: `gemini-*-flash` シリーズを使用します。高速なレスポンスが求められる通常のチャットで使用します。
- **Local LLM**: OpenAI 互換 API を通じて利用します。エンドポイントとモデル名は動的に変更可能です。

## 4. データベースとスキーマ (Prisma)
- **スキーマ変更**: `prisma/schema.prisma` を変更した際は、必ず以下の手順を行ってください。
    1. `npx prisma generate` を実行し、クライアントを更新する。
    2. 必要に応じて `npx prisma db push` やシードデータの再投入を行う。
    3. Docker コンテナ内の Client が最新になるよう、`docker-compose` の再起動やビルドを提案・実行する。
- **リレーション**: `User` と `Persona` は独立しています。それらを結びつけるのは `ChatLog` です。

## 5. 環境依存の処理
- **Docker 判定**: 環境変数 `IS_DOCKER="true"` を活用してください。
    - `true` の場合: ホスト名はサービス名（例: `chromadb`, `db`）を使用。
    - `false` の場合: `localhost` や `127.0.0.1` を使用。
- **CORS**: ブラウザからのアクセス時、ChromaDB 等の CORS 制約に注意してください。

## 6. フロントエンド設計
- **Styling**: Vanilla CSS または Tailwind CSS を使用します。
- **UX**: 状態更新（ヘルスや情緒の変化）がユーザーに直感的に伝わるようなアニメーションやアイコンを活用してください。
- GeminiApiのモデルをホワイトリスト化するときは、以下にしてください
  - Gemini Flash
  - Gemini Pro
  - Gemma
